## 19. 변경과 운영 반영

### 19-1. 현재 반영 경로

| 순서 | 작업 | 확인 |
|---|---|---|
| 1 | 작업 PC에서 코드 수정 | 18-2 해당 항목 |
| 2 | 커밋·푸시 (`<브랜치 규칙>`) | 커밋 메시지에 변경 내용 |
| 3 | 실행 PC에서 `git pull` (또는 파일 교체) | `git rev-parse --short HEAD` |
| 4 | 패키지 변경 시 `python -m pip install -r requirements.txt` | 오류 없음 |
| 5 | 창 1·2를 `Ctrl+C`로 끄고 다시 실행 | 9-1 실행 확인 |
| 6 | 브라우저 `Ctrl+F5` (캐시 갱신) | 바뀐 화면 확인 |
| 7 | 인계 이후 변경했다면 `docs/handover.md` 0장의 기준일 갱신 | - |

> [!NOTE]
> 빌드 단계는 없습니다. 백엔드와 화면 모두 **파일 교체 + 재시작**으로 반영됩니다.

### 19-2. 승인 흐름

| 변경 종류 | 승인 | 비고 |
|---|---|---|
| 화면 문구·디자인 | `<기입>` | - |
| 업무 규칙 (12장) | `<기입>` | 현업 확인 필요 |
| DB 스키마 | DB 담당 | 14-2 |
| 서버·네트워크 | 전산팀 | 4-3 |
| Kepware 기록 형식 | 설비 담당 | 13-4 |

### 19-3. 되돌리기

| 상황 | 방법 |
|---|---|
| 코드 반영 후 문제 | 실행 PC에서 이전 커밋으로 되돌린 뒤 재시작: `git checkout <이전 커밋>` (확인 후 정식 되돌리기 커밋) |
| DB 변경 동반 | 코드 되돌리기만으로 부족할 수 있음 → 14-2 경고 참고, DB 담당과 협의 |

### 19-4. 함께 고칠 표기

| 대상 | 위치 | 갱신 시점 |
|---|---|---|
| 화면 왼쪽 아래 표기 문자열 | `frontend/js/components/sidebar.js` | 화면 표기를 바꿀 때 |
| 인계 기준일 | `docs/handover.md` 0장 | 인계 이후 코드·기능을 바꿀 때 |
| DB 스키마 설명 | `mssql_query.sql` 머리말, MS_Description | 스키마 변경 시 |
