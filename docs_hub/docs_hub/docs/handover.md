## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 무엇을 하는 시스템인가 | 용접 공정의 기준정보 관리, LOT·용접·센서·비전 검사 결과 조회, 알람 이력 조회와 조치 기록 |
| 누가 쓰나 | 현장 운영자(OPERATOR), 관리자(MANAGER), 시스템 관리자(ADMIN, 기준정보 관리) |
| 데이터는 어디에 있나 | 사내 MSSQL 서버의 `HW_Q_DB` |
| 어떻게 만들어졌나 | 백엔드 Python FastAPI · 프론트엔드 HTML·JavaScript · DB MSSQL |
| 설비 데이터 경로 | 센서 → PLC → Kepware → HW_Q_DB |
| 접속 주소 | 화면 `http://127.0.0.1:5173` · 백엔드 `http://127.0.0.1:8000` (실행 PC에서만) |
| 지금 된 것 | DB 연결, 로그인, 기준정보 조회·등록·수정, **PLC ↔ Kepware 연결, Kepware → DB 전송 구현** |
| 아직 안 된 것 | **센서 ↔ PLC 연결**, 센서부터 화면까지 값 검증, 여러 PC 접속 (22장) |

### 1-1. 이 시스템의 책임 범위

| 구분 | 이 시스템이 하는 일 | 이 시스템이 **하지 않는** 일 (담당) |
|---|---|---|
| 설비 | 없음 | 설비 제어, PLC 프로그램 (설비 담당) |
| 데이터 수집 | 없음 (DB를 읽기만 함) | 설비 데이터를 DB에 기록 (Kepware, 설비 담당) |
| 조회 | 대시보드, 용접·비전·Lot·알람 조회, PDF·Excel·CSV 출력 | 실시간 설비 제어 판단 |
| 기록 | 로그인 이력, 기준정보 등록·수정, 알람 확인·조치 | LOT·용접·센서·비전·알람 **발생** 기록 |
| 계정 | 앱 로그인 인증 | 계정 발급 화면 (SQL로 처리, 15장) |
| DB | 테이블 읽기·쓰기 | 스키마 변경, 백업·복원 (DB 담당) |
| 인프라 | 없음 | 서버, 네트워크, 방화벽, 인증서 (전산팀) |

> [!IMPORTANT]
> 화면에 값이 없거나 틀리면 **이 시스템 문제인지, 데이터를 넣는 쪽(Kepware) 문제인지** 먼저 나눠야 합니다. 18-3의 SQL로 DB에 값이 있는지 확인하세요. DB에 값이 없으면 13장(설비 연동) 담당 영역입니다.

## 21. 알려진 문제와 제약

| ID | 문제 | 영향 범위 | 임시 조치·우회 | 해결 방향 |
|---|---|---|---|---|
| K-1 | `resolved_time`을 설비 해제와 조치 완료 두 의미로 쓸 수 있음 | 알람 상태, MTTR | Kepware가 `resolved_time`을 쓰지 않도록 합의 | 연동 사양에서 의미 확정, 필요 시 칼럼 분리 |
| K-2 | `DB_BACKEND`가 없으면 SQLite로 조용히 동작 | 전체 | 매 실행 `/health` 확인 | 값 없으면 오류로 변경 |
| K-3 | `.env.example`이 개발 기준 | 신규 설치 | 8-3 예시 사용 | 견본 교체 |
| K-4 | 알람 조치 등록에 역할 검사 없음, 조회 전용 역할 없음 | 권한 | 계정 발급 시 역할 관리 | 역할 검사·VIEWER 추가 |
| K-5 | 첫 로그인 비밀번호 변경 미강제, 비밀번호·사용자 관리 화면 없음 | 계정 보안 | 발급 시 안내, SQL로 관리 | 화면 추가 |
| K-6 | DB 쿼리 시간 제한 없음 | 응답 지연 시 화면 멈춤 | 백엔드 재시작 | 연결에 시간 제한 설정 |
| K-7 | 운영 주소 CORS 미등록, HTTPS 미적용 | 서버 운영 | 로컬 운영 | 4-3, 서버 결정 후 적용 |
| K-8 | 사용자 전환 시 메뉴가 바로 바뀌지 않음 | 화면 | 로그아웃 후 재로그인, `Ctrl+F5` | 메뉴 다시 그리기 |
| K-9 | 조치 구분·소속·사번이 `action_desc` 안에 저장 | 데이터 활용 | 접두어 형식 유지 | 칼럼 분리 |
| K-10 | `m_user.password_hash` DB 설명이 bcrypt/argon2 (실제 scrypt) | 문서 | 이 문서 기준 | MS_Description 정정 |
| K-11 | 용접부위 등록 시 설비 연결이 잘못될 수 있다는 기록 | 기준정보 | 등록 후 목록의 설비명 확인 | 재테스트 후 수정 |
| K-12 | 패키지 버전 미고정 | 재설치 | `requirements.lock.txt` | 버전 고정 |
| K-13 | 설비 알람의 현장 복구 시각 판단 불가 | 알람 상세 | - | PLC 해제 신호 저장 방식 결정 |
| K-14 | Windows 인증 미지원 | DB 접속 | SQL 계정 사용 | 필요 시 연결 옵션 추가 |

## 23. 인수인계 체크리스트

### 23-1. 인계자 (넘기기 전)

- [ ] 0장의 대상 브랜치·커밋을 기입했다
- [ ] 저장소 접근 권한을 부여하고 공개 범위를 확인했다
- [ ] 저장소에 `.env`, `data/.secret`이 없다
- [ ] `.env` 값을 별도 경로로 전달했거나 DB 담당과 연결했다
- [ ] 데모 계정을 사용 중지했다 (16-4)
- [ ] 인수자 ADMIN 계정을 발급했다
- [ ] `requirements.lock.txt`를 만들었다
- [ ] Kepware 설정 위치, Kepware DB 계정 관리자를 전달했다
- [ ] 19-2 승인 흐름과 24장 담당을 기입했다
- [ ] 21·22장을 인수자와 함께 읽고 우선순위를 합의했다

### 23-2. 인수자 (받은 후)

- [ ] 저장소에 접근해 Clone했다
- [ ] Python 3.10+, ODBC Driver 18을 설치했다
- [ ] DB 접속 계정을 받았다 (`sa` 아님)
- [ ] `.env`를 8-3 기준으로 작성했다
- [ ] `/health`에서 `"backend": "mssql"`을 확인했다
- [ ] 로그인하고 화면 6개가 열린다
- [ ] 18-3 SQL로 DB 최근 데이터를 조회할 수 있다
- [ ] 백업 주기·보관 기간을 DB 담당에게 확인했다
- [ ] 12장 업무 규칙과 21장 알려진 문제를 읽었다
- [ ] 19-1 절차로 작은 변경 1건을 반영해 보았다 (예: 문서 이력 갱신)
